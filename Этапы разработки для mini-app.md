## 1. Как пользоваться этим документом

Этот документ нужен не просто как список этапов, а как система контроля качества.

При разработке через нейросеть обязательны правила:
- реализовывать строго по этапам;
- не перепрыгивать через фундамент;
- не делать “чуть-чуть из следующего этапа”, если без этого можно обойтись;
- на каждом этапе добавлять логи;
- на каждом этапе выполнять максимум автоматических проверок;
- после каждого этапа обновлять чек-лист прямо в этом файле.

Когда нейросеть будет писать код, она обязана:
- сама менять статус текущего этапа в этом документе;
- отмечать выполненные подпункты чек-листа галочками;
- не ставить `[x]`, если пункт не проверен;
- оставлять `[!]`, если есть сомнения или непроверенные места;
- честно писать, что не удалось проверить без пользователя.

## 5. Границы файлов для mini-app

Чтобы не перепутать `mini-app` с ботом, при реализации нужно ориентироваться на следующие зоны.

### Основные mini-app зоны

- `frontend/miniapp/**`
- `src/app/web/**`
- `tests/miniapp/**`
- mini-app документы в корне проекта с названием `... для mini-app`

### Разрешенные общие backend-зоны

- `src/app/application/**`
- `src/app/domain/**`
- `src/app/modules/**`
- `src/app/infrastructure/**`

Только если это действительно нужно для общего ядра.

### Bot-файлы, которые трогать можно только по необходимости

- `src/app/bot/handlers/start.py`
- `src/app/bot/keyboards/**`
- `src/app/bot/runtime.py`

### Что нельзя делать

- переименовывать старые документы бота;
- переносить бизнес-логику во frontend;
- дублировать правила слотов и статусов отдельно для Mini App;
- массово переделывать существующий код бота без реальной причины.
